# 从参数变体转向路线搜索

本轮修改的是主决策流程：先比较不同解题路线，再选择路线内的改进。一个候选可以替换完整方法或耦合流水线，不限制为一个小补丁。路线图保存在 `research.md`，恢复卡保留当前路线、可负担的最强替代路线和选择理由；结果仍由冻结的指标与验证协议决定。

决策依据来自已有的[研究](automation-and-solving-experience.md)：MLE-STAR 的方法检索与组件深入、EoH 的新机制/机制修改/参数修改区分，以及算法获奖复盘中的表示和编码变化。本轮未重新运行这些上游项目，也未把特定算法写成跨任务默认方案。

## 主流程的变化

- **先选路线，再选变体。** 可执行的小调参不会自动压过有依据、可负担的结构性替代方案；约束、已有测量或预算使替代路线不值得测试时，记录原因即可。
- **一次候选承载完整机制。** 模型和预处理、表示和解码器、搜索表示和邻域可以作为一个完整方法一起替换。先评测整体，只有归因会影响下一步投资时才做消融。
- **按观测决定深入或换路。** 有明确改进空间时继续深入；连续微调收益微小或同一失败机制未解决时，返回表示、数据/训练信号、算法或策略选择，而不是继续生成相邻参数。
- **预算限制投入，不限制改动大小。** 未指定预算时仍是最多三个候选的初始搜索；已有授权、已耗预算与确认保留不变。更大的高分搜索需要明确预算，并非无限自动试验。

这改变了 `SKILL.md` 的决策循环、`score-search.md` 的路线选择与候选定义，以及 `decision-loop.md` 的恢复路由。它没有增加通用搜索服务器、自动提交或多 agent 依赖。

## 算法端到端试验

新增标准库示例 [`algorithm_route_pilot.py`](../examples/algorithm_route_pilot.py)，用生成的二维闭环旅行路线问题展示不同候选粒度。指标是所有案例路径长度的算术平均，越低越好；每条路径必须恰好访问每个顶点一次并回到起点。这是合成代理任务，不是实际比赛评分或通用 TSP adapter。

开发有 18 个实例：均匀、四簇、狭长三种几何分布，规模 `60/100/160`，各两个固定 seed，起始 seed `4100`。确认有 12 个实例：相同三种分布、规模 `80/140`，各两个新 seed，起始 seed `9100`。确认坐标在短名单冻结后生成；每组只确认 baseline 与其开发最优配置，按事先声明的“开发与确认均改善，否则 baseline”规则交付。

| 搜索组 | 六个候选名额的使用 |
| --- | --- |
| 参数组 | 最近邻 baseline，以及五个不同固定起点 |
| 路线组 | 同一 baseline、最远插入、MST 前序；从开发最好的构造路线继续测试 2-opt、增加顶点迁移、迁移后再次边交换 |

baseline 缓存只执行一次，但在两组各计一个名额，共 11 个不同开发配置。所有解法都从输入坐标完整运行，不能将父候选计算免费排除。每个局部搜索阶段最多检查 50,000 个可行邻域动作，整个候选最多 150,000 次检查；该工作上限不等同于统一时间预算。

## 弱结果之后怎样投入

这次继续修改主循环的去留决策：**当前候选能否晋升**和**路线是否值得投入**分别记录。一个有效低分可以证明它没有超过当前第一名，但不能单独证明整个方法不适合。恢复决策卡保留测试过的资源设置、停止证据和未解决机制，避免下一轮只读排名就淘汰路线。

在 [`score-search.md`](../skills/competition-optimize/references/score-search.md#decide-whether-to-repair-deepen-or-retire) 中，弱结果按证据区分为实现缺陷、基础设施/中断、工作上限、未充分测试的机制、已观察的平台期与在指定条件下可放弃的机制。训练/搜索进度、已知小实例和接口检查按题型提供证据。局部收敛不等于全局最优；进度平坦也可能是还没遍历完一个邻域。

补救需要明确缺陷或缺少的能力、继续/停止条件，并与第一名的下一项优化比较总成本。修改实现或资源设置仍计一个候选；诊断仍计时间/计算。比赛的硬资源上限不会因为“还在改善”而增加。预算不足时保留未解决状态，不将它记成实验否定，也不为每条路线强制安排一次补救。

## 让反馈改变下一项实验

进一步加强 [`Learn from Evaluated Pairs`](../skills/competition-optimize/references/score-search.md#learn-from-evaluated-pairs)，把实验经验接回主决策和恢复卡：

- **观察**：记录候选/父版本、匹配口径、开发结果和成本，说明原预测得到支持、被否定还是尚未解决。
- **解释**：记录原因假设及仍与证据相容的替代解释，不把模型反思当成因果证明。
- **下一项测试或限定经验**：明确改动、适用条件、预计观察、否定办法与成本；无预算时保留经验，不能自动追加试验。

失败后修改原假设，而非仅换候选名；局部提分但未胜过 incumbent 时保留这两个结论。继续同一题核对证据依赖，跨题重新核对规则、指标、规模和资源，并安排有预算的迁移验证。正反经验一起保存，避免只留下成功案例。这里的“学习”是更新实验判断与记录，不是在线修改模型权重。

### 从工作上限诊断到搜索顺序改动

此前的完整路线试验中，较弱 MST 构造接上 2-opt 后仍有部分案例在上限附近接受改进。因此提出一个具体假设：每次接受动作后从索引 0 重新搜索，可能在有限检查次数内反复检查相同前缀，其他锚点的邻域探索不足。替代解释是更改顺序会进入不同的局部区域，而不一定减少无效扫描。

加入 `two_opt_rotate` 候选机制：接受动作后从下一个锚点继续，未找到改进时仍完整遍历所有允许的 2-opt 动作。构造方法、输入、目标、动作集合、接收条件和总检查上限保持一致，改变检查顺序。搜索与最终计分继续分开。

`--study feedback_search` 是一个条件脚本试验：开发有 18 个实例，确认有 12 个；三种分布及规模与此前一致，开发 seed 起点 `8100`、确认 `13100`。生成开发实例前固定协议，第一次运行后没有为获得提分调整种子、机制或上限。最多三个开发候选：

1. baseline：已有支持的最远插入 + 固定起点 2-opt。
2. 对照：MST 前序 + 同样的 2-opt，读取开发停止和进度记录。
3. 条件候选：只有对照有案例耗尽上限，且最后四分之一检查仍接受过动作，才测试 MST + 轮转锚点 2-opt；没有信号时不消耗第三个名额。

每个候选都从输入重新执行构造和搜索，最多 150,000 次邻域检查。这个门槛用于检验已提出的试验，不是通用投资规则。改动由本次工程工作实现；示例不自主检索或生成算法。`feedback-decision.json` 在第三个 trial 前保存观察、解释、预测和否定条件，`development-lesson.json` 在评测后保存有范围的结果与经验，两者均在短名单冻结前产生。

| 开发候选 | 平均路径长度 |
| --- | ---: |
| baseline：最远插入 + 原搜索 | **7.188241** |
| 对照：MST + 原搜索 | 7.667835 |
| 条件改动：MST + 轮转搜索 | 7.410237 |

本次诊断触发第三个候选。相对其匹配对照，改动后的开发长度降低约 **3.36%**，支持这次实施在该开发协议下有效；它仍比 baseline 差，因此未晋升。改善没有直接证明重复前缀是原损失的原因，也不说明换一题、规模或邻域会有相同收益。

三个名额已经消耗，按预留进入冻结确认，不继续追加参数或组合。只有 baseline 进入确认，平均长度 `7.429540`。较弱路线的 3.36% 是开发结果，没有独立确认；**最终方案未获得额外提分**。开发评测累计约 `2.145 s`，不包括人工实现、检索、启动和完整交付；相同检查上限不代表相同全部成本。
