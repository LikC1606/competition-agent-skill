# Source-Backed Strategy-Generation Patterns

Read this when the task needs more than local edits to generate or select its next approach. The examples below come from inspected public source snapshots. They support the stated implementation pattern, not a claim that copying it improves another contest score.

## Produce structurally different candidates

- [KAPSO](https://github.com/leeroo-ai/kapso/tree/a2d110f2c7b09ea0c713a4b426066249371b6987): its [lens planner](https://github.com/leeroo-ai/kapso/blob/a2d110f2c7b09ea0c713a4b426066249371b6987/src/kapso/execution/search_strategies/generic/prompts/ideation_lens_planner.md#L66-L87) grounds parallel roles in how analogous tasks were won, a structurally different alternative and failure modes. The [selector prompt](https://github.com/leeroo-ai/kapso/blob/a2d110f2c7b09ea0c713a4b426066249371b6987/src/kapso/execution/search_strategies/generic/prompts/ideation_selector.md#L22-L63) judges expected progress toward the target and gives different structures more weight when the current line is stalled; the [ensemble implementation](https://github.com/leeroo-ai/kapso/blob/a2d110f2c7b09ea0c713a4b426066249371b6987/src/kapso/execution/search_strategies/generic/ideation.py#L392-L420) actually fans out candidates and selects or synthesizes. Transfer the separation of candidate generation from candidate selection. Adapt its evidence and budget checks to the actual competition contract.
- [CoMind](https://github.com/comind-ml/comind/tree/f93dff779b5d40dd3bf28b7b6ba5e39881e02e38): [solution-path generation](https://github.com/comind-ml/comind/blob/f93dff779b5d40dd3bf28b7b6ba5e39881e02e38/comind/agent.py#L303-L428) creates complete approaches before decomposing and recombining ideas, with an explicit fresh-route branch. This matters when atomic edits all inherit the same architecture. Its fixed route count is a repository choice, not a universal requirement.
- [LLM4AD Next](https://github.com/Optima-CityU/llm4ad_next/tree/c23a45c64a4b1fed322bfefbfe8436eeea32c954): [island policies](https://github.com/Optima-CityU/llm4ad_next/blob/c23a45c64a4b1fed322bfefbfe8436eeea32c954/src/llm4ad/orchestrator/island_diversity.py#L43-L114) separate successful-memory reuse, corrective memory and memory-free exploration. Its [planner](https://github.com/Optima-CityU/llm4ad_next/blob/c23a45c64a4b1fed322bfefbfe8436eeea32c954/src/llm4ad/planner/llm_evolution.py#L195-L221) can disable memory and even generate parentless candidates. The transferable point is to preserve an escape from stale assumptions; do not copy its island count or probabilities.

## Keep useful complementarity and branch value

- [EoH-S](https://github.com/feiliu36/eoh-s/tree/7d4b1f77d1b101125cd713b1d247e3a2e46cf407) keeps a compact set by first retaining the best average candidate, then preferring candidates that add the most per-instance max-score coverage ([survival selection](https://github.com/feiliu36/eoh-s/blob/7d4b1f77d1b101125cd713b1d247e3a2e46cf407/code/llm4ad/method/eohs/population.py#L108-L140)); it also selects complementary parents from per-instance score vectors ([parent selection](https://github.com/feiliu36/eoh-s/blob/7d4b1f77d1b101125cd713b1d247e3a2e46cf407/code/llm4ad/method/eohs/population.py#L271-L300)). Apply only when per-instance or per-regime outcomes matter downstream; for one fixed deterministic instance, extra diversity has no value by itself.
- [MCTS-AHD](https://github.com/zz1358m/mcts-ahd-master/tree/ee9c4f424503c65a5fd2b899e6620ce86079fedb) keeps searchable ancestors outside the current top-k pool, with progressive widening and remaining-evaluation-dependent exploration ([tree/search code](https://github.com/zz1358m/mcts-ahd-master/blob/ee9c4f424503c65a5fd2b899e6620ce86079fedb/source/mcts.py#L51-L70), [AHD selection](https://github.com/zz1358m/mcts-ahd-master/blob/ee9c4f424503c65a5fd2b899e6620ce86079fedb/source/mcts_ahd.py#L150-L185)). This separates “not currently elite” from “cannot lead to a useful descendant.”
- [The AI Telco Engineer](https://github.com/NVlabs/The-AI-Telco-Engineer/tree/be94f40f4bdd255b3e4dfa8bf32798821813311b) proposes distinct algorithmic families for a metric/complexity frontier, then presents both frontier candidates and selected faithful implementations from other families to the next proposal round ([generation prompt](https://github.com/NVlabs/The-AI-Telco-Engineer/blob/be94f40f4bdd255b3e4dfa8bf32798821813311b/src/orchestrator/orchestrator_llm.py#L27-L84), [actual loop](https://github.com/NVlabs/The-AI-Telco-Engineer/blob/be94f40f4bdd255b3e4dfa8bf32798821813311b/src/orchestrator/agent_orchestrator.py#L243-L279)). Its separate [implementation summary](https://github.com/NVlabs/The-AI-Telco-Engineer/blob/be94f40f4bdd255b3e4dfa8bf32798821813311b/src/orchestrator/orchestrator_llm.py#L91-L115) checks whether the assigned mechanism reached the code, independently of its score. Preserve the distinction between a weak tested family and an idea whose central mechanism was never implemented. Complexity is a task-specific proxy; replace it with the actual contest cost/constraint when needed. The LLM's fidelity verdict still needs code evidence, and the repository's fixed idea counts are not a general requirement.

## Make feedback change the next proposal

- [HeurAgenix](https://github.com/microsoft/HeurAgenix/tree/e84bfb19e785ae2d670af6e3ab68890c71c536ea) supplies positive and negative solutions plus trajectories to locate a bottleneck operation, then revises the rule governing that operation ([evolver](https://github.com/microsoft/HeurAgenix/blob/e84bfb19e785ae2d670af6e3ab68890c71c536ea/src/pipeline/heuristic_evolver.py#L249-L327)). Adapt this by comparing the decisions or objective terms that separate a strong candidate from a weak one; a final score without a mechanism is a poor lesson.
- [MLEvolve](https://github.com/InternScience/MLEvolve/tree/f4a37b96c948bfed6564e62f3229e0b38e908d33) escalates stalled work from parameter edits toward module/representation and paradigm changes, and can synthesize a route from independent successful branches ([tier policy](https://github.com/InternScience/MLEvolve/blob/f4a37b96c948bfed6564e62f3229e0b38e908d33/agents/evolution_agent.py#L68-L122), [branch aggregation](https://github.com/InternScience/MLEvolve/blob/f4a37b96c948bfed6564e62f3229e0b38e908d33/agents/aggregation_agent.py#L76-L150)). Use the escalation when observations point to a ceiling, not after an arbitrary number of trials.
- [RefineEvo](https://github.com/samwu-learn/refineevo/tree/7de015d5230e32b8b85fa83a3ecc55d117489138) labels experience by whether a candidate strictly beats its parent, retrieves it by semantic relevance and operator goal, then updates or removes experience based on reuse outcomes ([experience pool](https://github.com/samwu-learn/refineevo/blob/7de015d5230e32b8b85fa83a3ecc55d117489138/pool_interface.py#L76-L120), [reuse feedback](https://github.com/samwu-learn/refineevo/blob/7de015d5230e32b8b85fa83a3ecc55d117489138/pool_interface.py#L220-L285)). Transfer conditional, parent-relative lessons instead of storing unsupported universal rules.

For code or model search with costly evaluation, separate proposal ranking from score evidence. In the [Predict-Before-Execute repository's bundled AIDE fork](https://github.com/zjunlp/predict-before-execute/tree/c4d52cf99bd870d830b456ac7c0684aec1aef375/mle-bench/agents/aide), `_improve_batch` creates several distinct improvement sketches and implementations ([candidate generation](https://github.com/zjunlp/predict-before-execute/blob/c4d52cf99bd870d830b456ac7c0684aec1aef375/mle-bench/agents/aide/aide/agent.py#L368-L433)); its world model predicts pairwise winners, leaves low-confidence comparisons unresolved, and tournament-ranks the candidates ([pairwise confidence handling](https://github.com/zjunlp/predict-before-execute/blob/c4d52cf99bd870d830b456ac7c0684aec1aef375/mle-bench/agents/aide/aide/world_model.py#L303-L390), [tournament](https://github.com/zjunlp/predict-before-execute/blob/c4d52cf99bd870d830b456ac7c0684aec1aef375/mle-bench/agents/aide/aide/world_model.py#L455-L651)). The caller executes only candidates within a predicted top-k, samples execution, and forces the top candidate to run if that sample skipped all candidates ([execution gate](https://github.com/zjunlp/predict-before-execute/blob/c4d52cf99bd870d830b456ac7c0684aec1aef375/mle-bench/agents/aide/aide/agent.py#L633-L748)). This is an LLM-based screening policy that trades evaluator calls for model calls; it does not establish that the ranking is accurate or that it improves another task. Preserve exploration or periodically check the ranking against real outcomes.

Do not copy this snapshot's comparison cache as written. The cache key sorts the two code hashes, but the cached `winner_idx` is relative to the original `(node_a, node_b)` order; reversing the pair can therefore return an index for the wrong candidate. The cache is also a class-level map keyed only by code, so comparisons can be reused across different task descriptions or model settings. This is a static code-path issue, not a locally reproduced failure. A safe adaptation must canonicalize both key and winner identity (or invert the index on reversed lookup) and include all prediction context in cache scope.

[RD-Agent's feedback contract](https://github.com/microsoft/RD-Agent/tree/484776c211e4fbbeef03e0ec00d6bbee7362a4f4) compares a candidate with the current best using code diffs, aligned metrics and metric direction ([feedback](https://github.com/microsoft/RD-Agent/blob/484776c211e4fbbeef03e0ec00d6bbee7362a4f4/rdagent/scenarios/data_science/dev/feedback.py#L28-L113)); if it identifies that evaluation is misaligned with the task, it clears the result and rejects promotion. A useful search record can add parent-relative gain, strategy family, failure signature and evaluation cost so selection balances demonstrated progress with underexplored routes. Keep hidden/test labels out of proposal selection.

## Check the idea before translating it into code

- [CodeSIM](https://github.com/kagnlp/codegenerator/tree/9cf09ee6c788bfda3b7e1524e88be3447098eb24) manually simulates a proposed plan on sample inputs before coding, then traces failures to distinguish a bad plan from a bad code translation ([controller and prompt](https://github.com/kagnlp/codegenerator/blob/9cf09ee6c788bfda3b7e1524e88be3447098eb24/src/promptings/CodeSIM.py#L190-L305), [debug classification](https://github.com/kagnlp/codegenerator/blob/9cf09ee6c788bfda3b7e1524e88be3447098eb24/src/promptings/CodeSIM.py#L479-L505)). For optimization, walk a few states or updates through the proposed rule and check its invariant and coupled objective terms. This catches reasoning errors; it does not replace execution or scoring.

## Sustain a search across contexts

- [MLEvolve's action selection](https://github.com/InternScience/MLEvolve/blob/f4a37b96c948bfed6564e62f3229e0b38e908d33/engine/agent_search.py#L173) changes stalled branches to evolution/fusion. [ShinkaEvolve's historical-best tracking](https://github.com/SakanaAI/ShinkaEvolve/blob/8adc053a2ce4511ad2ac310e004c530a73fb974a/shinka/database/dbase.py#L2479) records the last real best improvement; its [stagnation handler](https://github.com/SakanaAI/ShinkaEvolve/blob/8adc053a2ce4511ad2ac310e004c530a73fb974a/shinka/database/dbase.py#L2563) spawns another island. The transferable mechanism is changing search behavior when new implementations stop yielding progress. It does not require terminating the search or asserting a route is exhausted.
- Do not copy MLEvolve's [global check](https://github.com/InternScience/MLEvolve/blob/f4a37b96c948bfed6564e62f3229e0b38e908d33/engine/conditions.py#L100) literally: it compares recent nodes with an already-updated global best. Replaying historical running bests distinguishes a real recent improvement from a score that merely rebounds below the best. This is a static code-path concern, not a reproduced third-party performance result.
- [AgentDiscover session.open](https://github.com/mhdfb/AgentDiscover/blob/9fc570321cc5bc585cdd535ac175f6d2fa8e5887/agentdiscover/orchestrator/session.py#L126) constructs and persists a brief before returning the session prompt; its [renderer](https://github.com/mhdfb/AgentDiscover/blob/9fc570321cc5bc585cdd535ac175f6d2fa8e5887/agentdiscover/orchestrator/session.py#L80) puts stable instructions before changing strategy text. [ReEvo's reflection update](https://github.com/ai4co/reevo/blob/6dce18257da5e11db2d138e417a2fffc5c72d05f/reevo.py#L380) merges prior/new observations and [mutation](https://github.com/ai4co/reevo/blob/6dce18257da5e11db2d138e417a2fffc5c72d05f/reevo.py#L441) injects them into generation. The next worker must actually receive the useful evidence; a stored log or an instruction to remember it is insufficient.
- RefineEvo's [retrieval](https://github.com/samwu-learn/refineevo/blob/7de015d5230e32b8b85fa83a3ecc55d117489138/pool_interface.py#L220) filters semantic matches only by operator goal, after a global top-k query. Its natural-language applicability text is not an enforced task/split/metric contract; [reuse feedback](https://github.com/samwu-learn/refineevo/blob/7de015d5230e32b8b85fa83a3ecc55d117489138/evo_interface.py#L792) credits the same candidate outcome to all retrieved memories. Preserve evidence scope and parent-relative observations; do not turn one failed reuse into proof that every retrieved lesson is wrong.

The [campaign driver](unattended-campaign.md) adapts these ideas using the existing archive: verified development retrieval, scored implementation history, objective-triggered reviews and independently configurable context rotation. It uses no additional LLM calls or third-party runtime. Four nonimproving implementations and eight checkpoints are adjustable engineering defaults, not source-derived optima. These mechanisms have no measured contest-score or token-saving claim.

## Retrieve open branches separately from score leaders

- [ShinkaEvolve's parent selector](https://github.com/SakanaAI/ShinkaEvolve/blob/8adc053a2ce4511ad2ac310e004c530a73fb974a/shinka/database/parents.py#L367-L423) weights eligible parents using normalized performance and `1/(1+children_count)`, then samples a parent. Its [database selection path](https://github.com/SakanaAI/ShinkaEvolve/blob/8adc053a2ce4511ad2ac310e004c530a73fb974a/shinka/database/dbase.py#L1234-L1284) chooses a parent independently of archive/top-k inspirations. The useful distinction is between a search root worth reviewing and a strong scored reference. Its weights, random sampling, island settings and raw child counts are not transferred.
- [MCTS-AHD expansion](https://github.com/zz1358m/mcts-ahd-master/blob/ee9c4f424503c65a5fd2b899e6620ce86079fedb/source/mcts_ahd.py#L76-L124) draws from ancestor paths or multiple roots, records evaluated descendants and [propagates their outcomes](https://github.com/zz1358m/mcts-ahd-master/blob/ee9c4f424503c65a5fd2b899e6620ce86079fedb/source/mcts.py#L51-L64). A lower-scoring ancestor can remain a useful starting point. Do not transfer its UCT formula, finite-budget exploration decay, negative-objective assumption or score-based duplicate checks to an open-ended generic campaign.

The adaptation is `review_frontier`: retrieve explicit open development opportunities before score-route truncation, merge implementation aliases, show actual distinct successors and rotate successful handoffs. Only observed non-unresolved successors after an opportunity's first declaration advance it; failed or unscored children do not disprove the parent mechanism. First-valid scored representatives remain separate from later feedback declarations. Exposure is a checkpointed retrieval order, not a visit-based reward, forced parent choice, causal conclusion or experiment allowance. See [retrieval semantics](iteration-trace.md#retrieve-evidence-for-the-next-implementation) and the [implementation study](../../../docs/source-study-20261022.md#旧分支与高分参考分开检索).

## Recover execution before judging the method

- [AIDE's search policy](https://github.com/WecoAI/aideml/blob/ad73d227af481bea3de06f884f41b2993dd6453a/aide/agent.py#L161-L192) selects buggy leaves for debugging and successful nodes for improvement; its [debug branch](https://github.com/WecoAI/aideml/blob/ad73d227af481bea3de06f884f41b2993dd6453a/aide/agent.py#L342-L365) receives the failed source and actual execution output. [Feedback parsing](https://github.com/WecoAI/aideml/blob/ad73d227af481bea3de06f884f41b2993dd6453a/aide/agent.py#L424-L445) treats an exception or missing metric as buggy. Transfer the separate work selection and concrete diagnostics. A missing metric can reflect incomplete measurement rather than an algorithm bug; do not assign it a fictitious bad score. Its debug probability, depth and total-step limits are not general requirements.
- [MLExpert's executor](https://github.com/internscience/mlexpert/blob/8911b70bdd441750685531f3ad5a076cc101aad6/kaggle-mle-factory/src/executor.py#L52-L93) feeds real execution errors into a code repair and reruns it; its [repair dispatcher](https://github.com/internscience/mlexpert/blob/8911b70bdd441750685531f3ad5a076cc101aad6/kaggle-mle-factory/src/repair.py#L42-L65) distinguishes data preparation from scoring failures. This is a task-authoring pipeline. Borrow responsibility-aware diagnosis, not its output deletion, retry cap or permission to rewrite a competition's fixed evaluator.

The driver implements a separate chronological execution-health signal and immediate repair mode. Failures can lack a complete comparison contract, so the signal spans those changes without comparing scores. Verified errors and a scored development reference reach the next worker; repeated missing observations request a fresh diagnosis. A usable observation ends that streak even when its score is weak. The default three-attempt review is configurable and never stops the campaign. Evidence and transfer limits are recorded in the [implementation study](../../../docs/source-study-20261022.md#执行失败分流与长期档案).

## Resume the proposed work at the recorded step

[RD-Agent's data-science loop](https://github.com/microsoft/RD-Agent/blob/484776c211e4fbbeef03e0ec00d6bbee7362a4f4/rdagent/scenarios/data_science/loop.py#L158-L198) passes the generated experiment and its pending tasks into coding, then the same coded experiment into execution. Its [workflow step handler](https://github.com/microsoft/RD-Agent/blob/484776c211e4fbbeef03e0ec00d6bbee7362a4f4/rdagent/utils/workflow/loop.py#L205-L309) retains per-step outputs and advances the stored step before saving a snapshot; [loading](https://github.com/microsoft/RD-Agent/blob/484776c211e4fbbeef03e0ec00d6bbee7362a4f4/rdagent/utils/workflow/loop.py#L455-L501) restores that workflow state. The transferable idea is preserving a concrete experiment and its completed stage across contexts, rather than asking the next agent to regenerate it from a summary. The handler also has explicit exception branches, so snapshot existence alone does not certify a valid scored experiment.

The local adaptation retains the existing append-only proposal/result ledger: rotate unfinished details after successful handoff, recover original targets with `trace --proposal-id`, and commit review checkpoints only after accepted CLI completion. A proposal's first parent supplies its comparison ownership; cross-contract repair/transfer references retain identities and pointers without supplying active scores. This ownership and retrieval policy is a local design choice, not a reproduction of RD-Agent's scheduler. No pickle loading, destructive checkout, automatic pipeline cleanup or additional framework dependency is transferred. See [recovery semantics](iteration-trace.md#retrieve-evidence-for-the-next-implementation) and [the implementation study](../../../docs/source-study-20261022.md#未完成提案接回真实执行).

## Establish a common development comparison

[RD-Agent's ValidationSelector](https://github.com/microsoft/RD-Agent/blob/484776c211e4fbbeef03e0ec00d6bbee7362a4f4/rdagent/scenarios/data_science/proposal/exp_gen/select/submit.py#L298-L342) prepares validation inputs once, gives every candidate the same folder and grading script, and selects from those new measurements. Its [worker](https://github.com/microsoft/RD-Agent/blob/484776c211e4fbbeef03e0ec00d6bbee7362a4f4/rdagent/scenarios/data_science/proposal/exp_gen/select/submit.py#L560-L611) runs each candidate and the shared grader in a new workspace. With only one successful score, selection returns no winner. The [development runner](https://github.com/microsoft/RD-Agent/blob/484776c211e4fbbeef03e0ec00d6bbee7362a4f4/rdagent/scenarios/data_science/dev/runner/eval.py#L152-L155) separately checks the metric column and [keeps an unavailable score as None](https://github.com/microsoft/RD-Agent/blob/484776c211e4fbbeef03e0ec00d6bbee7362a4f4/rdagent/scenarios/data_science/dev/runner/eval.py#L223-L226).

The transfer is to recover a common legal development evaluation before deciding which implementation improves the objective. This framework's `comparison_continuity` detects newly observed complete contracts that still lack a second measured implementation. Stable smoke runs cannot clear a full-contract gap; genuinely evaluating a different archived implementation under that full contract can. The fresh `measure` prompt supplies verified source/result pointers and changed contract fields, with cross-contract objective values and feedback excluded. A pre-bounding digest of essential pointers prevents truncated recovery cards from consuming a review. Successful handoff records only the sealed pre-turn observation count; actual paired evaluation resolves the gap. The default window of four and singleton accounting are local engineering choices.

RD-Agent also generates validation data/grading scripts and uses historical or medal results in parts of its candidate selection. Those paths are outside this transfer: preserve this task's existing fixed evaluator, allowed development data and full comparison identity. The cited code is static source evidence, with no third-party agent execution or contest-score reproduction.

## Retrieve the version that produced the result

- [NVIDIA Kaggle skill](https://github.com/NVIDIA/nvidia-kaggle/tree/2b78cf29f5f30680764292a6592de8d53d4147a) traces ranked writeups to actual team standing and notebook lineage, then fetches the historically best-scoring notebook version ([version selection](https://github.com/NVIDIA/nvidia-kaggle/blob/2b78cf29f5f30680764292a6592de8d53d4147a/skills/nvidia-kaggle-skill/scripts/kernels/archive.py#L185-L345)). When learning an external solution, identify the rank evidence and exact source snapshot associated with the result; the latest repository state may not be the winning version.

These examples motivate a generation workflow: explore complete, distinct mechanisms; preserve complementary branches only when they can affect the objective; feed scoped success/failure evidence into a new proposal; and let the task determine which layers and comparisons matter. They do not imply that one fixed search framework, memory policy or number of branches is best for every contest.
