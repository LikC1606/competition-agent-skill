# Choose and Evaluate a Prediction Ensemble

Read this when a strong source or development errors suggest that combining models could improve the declared metric. Use the comparison to select one consequential experiment in the existing proposal or research state.

## Identify What the Combination Changes

Trace the scored output through each member's representation and fit, the combiner's inputs and fit, the final mixture, and the output transform. For a public solution, read the version that produced the score and inspect code that writes the submission. Match previous trials to those same operations before treating a route as tested. Different member views, a nonlinear combiner, or adding context to the second layer can change what the system can learn even when some models have the same names.

| Mechanism | Reason to try it | Matched control |
| --- | --- | --- |
| Fixed combination of matched predictions | Members make errors that can offset one another at low construction cost | Strongest base model and the current incumbent. Equal weighting is a cheap reference when the output scale and metric support it. |
| Stack on predictions, optionally mixed with a fixed blend | Relative predictions or model disagreement may predict a nonlinear correction. A fixed contribution from the base blend limits the stack's influence. | Same base predictions with a fixed blend. If the question is nonlinearity, compare with a regularized linear stack. Isolate a hybrid's contribution by pairing it with its base blend and stack alone when that changes the choice. |
| Stack on predictions and permitted inference features, or learn a gate | Model usefulness or bias may vary with observable context, such as a missingness pattern or a regime defined by available features. | Same base predictions and meta learner without those features. If the claim is better routing between models, test an explicit gate or compare against a fixed mixture with a context-only residual correction. Feature passthrough can improve by learning a direct effect. |

To let a linear stack's weights vary with context `z`, include products `p_i * z_j` between member predictions and permitted context features. This gives each prediction `p_i` a coefficient of the form `a_i + b_i · z`. Appending `z` alone can learn a common correction while keeping model weights constant. Compare those variants on the same base predictions when their distinction would change the design. [Netflix Prize conditional stacking](cross-competition-cases.md#netflix-prize-separate-persistent-signal-from-drift)

Keep the same base predictions and outer folds when testing a combiner in isolation. If base learners or feature views also change, compare the complete system with the incumbent and attribute the result to that joint change. Select additional controls only when their outcomes could change the decision. Record member recipes, the combiner's inputs, its fitting boundary, mixture and output scale, the expected difference, and the matched comparison in the existing proposal. Count every scored recipe and its aggregate inference cost.

A small pool of compatible saved predictions lets you compare equal-weight pairs on the same development rows without new fits. Under squared loss in a common prediction space, the row loss of `(p + q) / 2` equals the mean of the two member losses minus `(p - q)^2 / 4`. The pair beats its stronger member on mean squared error when the mean disagreement term exceeds half the difference between the member mean losses. Score each chosen pair on the declared metric against the strongest member and incumbent. Use the selected pair as a development candidate and freeze the recipe before independent confirmation. [Existing blend tool](data-model.md#construct-and-confirm-a-prediction-blend)

For squared loss in a common prediction space, a direct gate hypothesis follows from `h = p0 + w(z) d`, where `d = p1 - p0` and `z` is available at inference. When `E[d² | z] > 0`, the loss-minimizing convex weight is `clip(E[(y - p0)d | z] / E[d² | z], 0, 1)`. Check predeclared, adequately represented regimes with the existing development error tool. Differences across regimes can motivate a small regularized gate. A result for constant weights applies to the tested weights and predictions. Use a metric-specific argument for other losses. See [development error diagnostics](data-model.md#diagnose-development-errors).

## Check What Fixed Members Can Recover

Apply the candidate coverage question to scalar convex blends. Align saved development predictions and labels by ID, split and scored units. On row `i`, all blends with nonnegative weights summing to one lie in `[lo_i, hi_i]`, the smallest and largest member predictions. Clipping the development label to this interval yields the smallest attainable absolute or squared residual. Use NumPy rowwise min/max and clip, then `prediction_core.calculate_metric` to get the RMSE or MAE lower bound. The incumbent score minus that bound caps the possible gain on these rows with these fixed members. The calculation gives the router access to each scored label, so it is an optimistic diagnostic. [Candidate coverage and ranking](cross-competition-cases.md#otto-candidate-coverage-and-ranking)

On a subset, sum the attainable loss reductions there and keep other rows' losses fixed when translating to a pooled score. Count labels outside the interval and quantify the loss separately. A label outside the interval can still be much closer to one member than to the incumbent. If the bound leaves too little room for the proposed cost, look for a member that extends the range toward the target or a correction that can leave the interval. Check a new member's effect with matching saved predictions when available. Otherwise use an affordable prototype or check the new mechanism's premise on development data before a full fit.

If the bound leaves room, ask whether permitted inference features can select a useful change. For squared loss along `d = p1 - p0`, examine the alignment term `(y - p0)d` by regime. An AUC near 0.5 for residual sign only describes how the tested signal ranks that sign. For example, let `y = (0, 2, 0, 2)`, `p0 = (1, 1, 1, 1)` and `p1 = (0, 2, 2, 0)`. The first two rows form one regime and the last two form another. Each regime has one residual of each sign, so the regime's sign AUC is 0.5. Yet the alignment is positive in the first regime and negative in the second. Using `p1` in the first and `p0` in the second gives squared error 2, while the best fixed convex blend has squared error 4. Judge a routing proposal by the scorer and an honest comparison with a fixed blend on the same members.

Keep the scope in the proposal. The bound concerns the tested rows and a specified set of fixed outputs mixed in the scored space. A refitted member, an additive correction or a stack that predicts outside the interval has a different feasible set.

## Compare an Edited Member in the Full Blend

For a fixed linear blend in the space where squared loss is measured, let `e = prediction - truth` be the full blend's residual. Replacing one member changes the blended prediction by `d = weight * (new_member - old_member)`. The change in total squared error is `sum(2 * e * d + d²)`. For a single target of zero, replacing a member's prediction of 1 with 2 worsens its individual squared error from 1 to 4. In an equal blend with a second prediction of -2, that replacement reduces squared error from 0.25 to 0.

When older augmentation trials used a different base or combiner, use their results to judge the tested fit. Replay a replacement when you have aligned saved predictions for the original and replacement members and can reproduce the control. When fitting adjusts other members, weights or a downstream correction, test the complete proposed path under the matched development contract. A diffuse regression in an older member establishes the regression on those rows and leaves the new integration open. [Reuse fitted artifacts](tabular-training.md#reuse-fitted-artifacts-for-prediction-only-changes)

For a gate that varies the mixture of `A` and `B` while holding the share `s` of `C` fixed, form the full scored endpoints `p0 = (1-s)*B + s*C` and `p1 = (1-s)*A + s*C`. Over any declared group, the best convex weight under squared loss is `clip(sum((y - p0)*d) / sum(d²), 0, 1)` with `d = p1 - p0`. If `d` vanishes in the group, all weights give the same predictions. With `y=1, A=2, B=1, C=0, s=0.5`, the A/B optimum chooses `B` but gives a final prediction of `0.5`. The full blend reaches `1` by choosing `A` in that slot.

For two saved endpoints, use [the RMSE headroom diagnostic](data-model.md#bound-the-headroom-of-a-grouped-blend) after establishing that their units and prediction contexts match. Use the bound by `(fold, group)` for a separate group map in each outer fold. Sharing each group's weight across folds restricts the allowed moves. A bound below the required gain rules out that fixed blend class on these rows. A bound above it leaves open whether a fitted rule can recognize useful moves on unseen rows.

Applying shrinkage after fitting the score-optimal weight produces a single label-informed result. To see the difference, let the endpoints be `0` and `1` for a target of `0.4`, with weights halved toward zero. Halving the unconstrained optimum `0.4` gives a prediction of `0.2`. Halving the feasible raw weight `0.8` hits the target. Use the optimum over reachable weights when bounding a specific shrinkage rule, or use the looser bound for the full convex range. A gain ratio observed on an earlier gate needs evidence of transfer before it can estimate the gain of a different gate.

To shrink a group's weight toward a constant `w0`, let `m = p0 + w0*d`. Minimize `sum((y-m-u*d)^2) + lambda*u^2` over `u` in `[-w0, 1-w0]`. The solution is `clip(sum((y-m)*d) / (sum(d^2) + lambda), -w0, 1-w0)` for positive `lambda`. Groups with no movement signal retain `w0`. The strength of the evidence about the weight depends on `sum(d^2)` as well as group size. Use the same fit inputs and loss for the global and grouped controls when testing specialization. A full blend fit includes the unchanged member's inner prediction under the declared fit rule. [Reuse the fit inputs](tabular-training.md#reuse-inner-predictions-for-a-learned-combiner)

Flat single-variable groups can hide a useful interaction. With two independent fair bits and `y=2` when they agree and `0` otherwise, each bit alone has mean target `1` in both groups. For predictions `p0=1` and `p1=2`, the best single-bit gate always chooses `p0`. A gate on agreement halves expected squared loss. Check a joint grouping when a task mechanism supports it and the groups have enough observations. Test any learned gate with its fitting boundary intact. [Fitted diagnostics](local-evaluation.md#fitted-diagnostics-on-stored-predictions)

## Compare Preprocessing Views

When missing inputs plausibly limit predictions, keep the learner, missingness indicators and folds fixed to compare simple filling with a learned alternative. Fit the learned filler inside each training partition and retain the distinction between structural absence and missing measurements. Inspect paired errors on the affected rows. If the two views appear complementary, replay a fixed blend from matched predictions and compare with the strongest member and incumbent before investing in a learned combiner. Where a view depends on a different learner, compare the complete branch and attribute the result to that joint change.

Firstbloody reports that grouping by neighborhood and lot configuration to fill missing frontage did not help and uses zero filling. Gehsbargs reports better results from an independent MICE plus SVR branch mixed with the existing stack than from feeding the MICE table into that stack. The reported comparison changes the imputation, learner and integration together. ## Reuse Predictions at the Right Fitting Boundary

1. Check IDs and the split, member and preprocessing lineage, and prediction units. Define the space in which outputs combine and how the metric and submission consume them. Averaging log prices then inverting and averaging prices define different predictors. Score in the declared metric space and use the recorded inverse for delivery. A fixed rule can reuse compatible saved outer-fold predictions. For an independent estimate of that rule, its selection must also exclude the scored labels. Choices revised on pooled OOF scores or slices inform development. Freeze the recipe before independent confirmation. Use the [CSV blend tool](data-model.md#construct-and-confirm-a-prediction-blend), the [two-parent direction check](data-model.md#check-whether-a-two-parent-blend-has-a-useful-direction) or [saved-model replay](tabular-training.md#reuse-fitted-artifacts-for-prediction-only-changes) as applicable.
2. For a learned second layer, fit it separately inside each outer training partition. Generate or reuse matched inner out-of-fold base predictions there, with supervised preprocessing inside each inner base fit. Predict the outer validation rows using the base learners fitted on that outer training partition and apply the frozen within-fold combiner. Ensure any learned context transform and recipe selection respect their own fitting boundaries. A pooled table of ordinary outer OOF predictions can support diagnostics and fixed replay. Training a stack or gate on a second split of that table can import the scored fold's labels. Label an unverified probe descriptive. See [the fitting boundary](local-evaluation.md#match-the-intended-test-conditions).
3. Use the existing tools. For partitions supported by scikit-learn, put preprocessing inside the base estimators passed to `StackingRegressor` or `StackingClassifier` and supply inner splits appropriate to the outer training partition. The library's internal `cv` generates meta-training features. The task protocol still defines the outer score. When using `passthrough`, check what the final estimator actually receives and prepare those features within the correct boundary. Use the task adapter with the existing split tools when grouped or time-aware validation cannot be expressed by the library's prediction partition. Reuse verified inner inputs and unchanged outer fits across combiner variants. Outer-only caches do not remove the cost of generating missing inner inputs. Count those fits before launch and use the smallest informative comparison allowed by the task.

Before a broad saved tabular OOF screen, including an interval bound or search for a new member, run [the fold and truth preflight](tabular-training.md#match-saved-oof-before-screening) against the scored control. Rank matched members together after checking the output context and units. Compare candidates from other folds with controls on their own folds, or keep the observation descriptive. The same scoring IDs appear in many repartitions. Even on matched folds, inspect fitted ancestry before treating a saved blend as a new member. A blend that includes an incumbent arm can inherit its predictions, and a pool or weight choice made using the scored labels remains a development diagnostic.

When the missing inner fits exceed the available budget, use a cached check if it can change the next action. Reproduce the fixed control, then use paired errors in a few task-supported slices to test whether the proposed context changes the useful direction of the mixture. An informative difference can justify reserving budget for a nested comparison. If the budget is already available and the mechanism is well motivated, proceed with the matched trial.

Use the declared metric on matched development predictions. Decide any later independent confirmation and actual delivery mix with the recipe frozen. Public scores and example weights can suggest a mechanism. They cannot supply the local selection evidence.

## Compare Fusion Scales Without Refitting

If members predict log targets, mixing before versus after the inverse transform can change the scored predictor even with the same weights. For natural-log outputs `p_i` and normalized nonnegative weights `w_i`, the log-space blend is `m = sum(w_i p_i)`. Blending in original units gives `log(sum(w_i exp(p_i))) = m + delta` in log units. Jensen's inequality gives `delta >= 0`, with equality when the members with positive weights agree. For a log target `t`, the change in squared error is `delta * (2 * (m - t) + delta)`. The upward correction helps a row when `delta > 0` and `t - m > delta/2`. Overall improvement depends on the paired errors on the scored population.

When this could change the choice, replay both rules with the same members, weights and aligned development rows. Use the actual inverse and metric transform, including any offsets. Hold other output operations fixed to isolate scale. For the natural-log case, use `scipy.special.logsumexp` with the normalized weights and the existing prediction evaluator. Check the full metric and where disagreement drives the difference. Separate this scale comparison from any change to the members, their data or their training. See [existing numeric operations](codex-tools.md#reuse-the-existing-numeric-operations).

For circular or spherical targets, compare representations that respect the geometry and test whether disagreement predicts which member is more accurate. [IceCube's direction fusion](cross-competition-cases.md#icecube-fuse-directions-by-geometry-and-disagreement)

If changing the view of an input only permutes its labels, map the predicted probabilities to the original label order before averaging. Confirm the label rule from the task, including whether order affects the observed outcome. Hold the model fixed and reuse paired predictions when available. Compare the original rule and the average with the existing scorer on identical held-out groups, and account for the additional inference cost. [LMSYS probability averaging](cross-competition-cases.md#lmsys-2024-swap-inputs-and-map-the-labels-back)
